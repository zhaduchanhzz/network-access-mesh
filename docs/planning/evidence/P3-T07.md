## 3. Cơ chế tiêm lỗi và vì sao an toàn

Mọi collaborator của `orchestrator.Config` vốn là interface (`Agent`, `Store`, `Placer`, `SecretStore`, `IdPDrivers`, `headscale.Registry`, `Prober`); `faultinject` cung cấp decorator cho từng cái. Một lỗi nêu **tên lời gọi** (28 tên, mỗi tên gắn với bước của §11.3 — `faultinject.Calls`; `EnsureInstance` tách theo phase), **mode**, **trước/sau** lời gọi thật, **số lần** và **số lần bỏ qua** — đếm theo lời gọi, không ngẫu nhiên, nên cùng kế hoạch luôn cho cùng kết quả. Lỗi được trả về **đúng dạng lỗi thật của tầng đó**, để state machine phân loại như với collaborator thật:

| Tầng | Vĩnh viễn (⇒ compensation) | Tạm thời (⇒ retry tại chỗ ⇒ `failed_resumable`) |
|---|---|---|
| Agent | `FAILED_PRECONDITION` + `Refusal{STATE}` (như agent từ chối) ⇒ `agent_state` | `UNAVAILABLE` ⇒ `agent_unavailable` |
| Registry (`Store`) | `orchestrator.ErrState` ⇒ `registry_state` | lỗi DB ⇒ `registry_unavailable` |
| Headscale | `headscale.Error{upstream_rejected}` ⇒ `headscale_upstream_rejected` | `headscale.Error{unavailable}` ⇒ `instance_unavailable` |
| Prober | `Edge`: probe chạy và thấy path cấm ⇒ `edge_exposes_paths` | prober không tới được ⇒ `prober_unavailable` |
| Placer / SecretStore / IdP | `platform.ErrConflict` / `secrets.ErrKeyDestroyed` / `idp` `conflict` | lỗi DB / lỗi DB / `idp` `unavailable` |

`after = true`: lời gọi thật chạy xong rồi mới trả lỗi — **tác dụng của nó tồn tại** (thư mục, container, API key trong Headscale, hàng registry) trong khi state machine chỉ thấy thất bại (ca "mất câu trả lời"). `kill`: tiến trình worker tự `SIGKILL` ngay sau lời gọi thật (ca "worker chết giữa bước").

**Vì sao an toàn — không có backdoor trong production:** không có hook, cờ, biến môi trường hay build tag nào trong `internal/` hay `apps/`; lỗi chỉ đi qua các interface orchestrator vốn phụ thuộc. `faultinject` nằm dưới `tests/`; `TestNotImportedByProduction` (chạy trong `go test ./...`) duyệt mọi file không phải test của `apps/` và `internal/`: không file nào import `tests/…`. Binary api/worker/agent vì thế không chứa mã tiêm lỗi.

## 6. Lỗi tìm thấy và đã sửa

**Compensation bước 16 không thu hồi lời mời Owner khi id chưa kịp ghi.** `stepConfigure` ghi `created_resources {owner_email}` **trước**, gọi `Store.Configure` (transaction tạo lời mời `pending`), rồi mới ghi `invitation_id`.
