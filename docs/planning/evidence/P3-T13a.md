## 2. Luồng job

**`instance.restart`** (nhóm lifecycle, khóa `tenant:<id>:lifecycle`, có compensation):

1. `instance.restart` — instance `running` (`quarantined` ⇒ từ chối), ghi thời điểm start trước đó, `RestartInstance` (start guard của Agent; từ chối ⇒ Critical, Agent đã khoanh instance);
2. `instance.health` — container healthy, start **sau** lần restart, đúng `config_sha256`, Noise key không đổi; `GET /api/v1/health` qua adapter — API key của nền tảng bị từ chối ⇒ DB bị thay (Critical, gỡ edge);
3. `policy.gate` — post-start gate (mục 3);
4. `edge.verify` — Prober (không cấu hình ⇒ `skipped`);
5. `restart.finish` — audit `.succeeded`.

Lỗi không phục hồi ⇒ compensation không có gì để lùi: đóng operation `.failed`, thông báo SA/PO, job `rolled_back` (nhả khóa — instance có DB bị thay phải `instance.restore` được). Lỗi tạm thời: retry tại chỗ rồi `failed_resumable`.

**`instance.upgrade`** (cùng nhóm, có compensation) — 11 bước:

| Bước | Việc |
|---|---|
| `upgrade.preflight` | Instance `running`, có version cấu hình; digest đích trong allowlist; `InspectImage` image hiện tại và image đích; `UpgradePath` (patch cùng minor / minor kế tiếp); version đích được adapter hỗ trợ; version đang chạy (adapter `GET /version`) = version của image; `ValidateConfig` với image đích (sha256 phải trùng config đang chạy — khác ⇒ `config_drift`, reconfigure trước); `CheckPolicy` của chuỗi đang áp dụng. Đã ở đích ⇒ kết thúc, không dừng gì |
| `instance.stop` | Ghi `created_resources` trước, rồi `StopInstance` |
| `backup.cold` | `Backup` khi đã dừng ⇒ `cold_copy` (dùng lại bản của lần thử trước nếu có) |
| `upgrade.configtest` | `OpenBackup` (chữ ký manifest, data key) + `PreflightUpgrade`: `configtest` của binary đích trên **bản sao giải mã** — migration và policy đang lưu được thử thật; `data/` gốc không bao giờ được mount |
| `image.switch` | Ghi tài nguyên trước; `UpgradeInstance` (CAS digest, `compose up --no-start`) |
| `instance.start` | Ghi `started` trước; `StartInstance` (start guard) |
| `instance.health` | Như restart, cộng digest = đích |
| `policy.gate` | Post-start gate |
| `upgrade.smoke` | `GET /version` = version đích; đọc users, nodes, pre-auth key, API key (prefix của nền tảng) qua adapter |
| `edge.verify` | Prober |
| `upgrade.finish` | Một transaction: version cấu hình mới (cùng sha256, image mới) `applied`, version cũ `superseded`, `image_digest`, audit `.succeeded` |

## 3. Tự lùi và post-start gate

| Thời điểm lỗi | Lùi |
|---|---|
| Trước `image.switch` (preflight, backup, `configtest` đích) | Start lại image cũ trên `data/` gốc (không đổi); job `rolled_back`, audit `.failed` |
| Sau `image.switch`, image mới **chưa từng start** | `UpgradeInstance` về digest cũ rồi start; health + post-start gate |
| Image mới **đã start** | Dừng → `UpgradeInstance` về digest cũ → `RollbackRestore` cold backup của job (`data/` hiện tại giữ ở `data.prev-*`, `PostRestoreReconcile`, gắn lại edge) → health + post-start gate; audit `platform.instance.upgrade_rollback` |
| Lùi lỗi | `failed_resumable` (`compensation_failed`) + `security_event` Critical `instance.upgrade_rollback_failed`; operation để mở cho `/rollback` |

Mọi lỗi kết thúc ⇒ thông báo `instance.operation_failed` cho Super Admin + Platform Operator (outbox). Instance chuyển `quarantined` giữa job ⇒ không start lại.

**Post-start gate** (cả hai job): `GetPolicy` so với `applied_sha256`; lệch ⇒ `security_event` High `instance.policy_drift` + `policies.Service.Apply` (trigger `drift_repair`, chuỗi `applied` hiện hành) rồi đọc lại — vẫn lệch ⇒ `policy_repair_failed`; `ErrNoPolicy` hoặc API key bị từ chối ⇒ Critical `instance.database_replaced`, `RemoveEdgeAttachment`, lỗi không phục hồi.

**Xác nhận `configtest` nạp policy đang lưu** (câu hỏi mở của §11.4): đọc mã nguồn Headscale 0.29.7 — `configtest` gọi `NewHeadscale` → `NewState` (migrate DB, đọc policy trong DB, `NewPolicyManager`); ca thử Docker thật (mục 6, ca 1) ghi một policy không hợp lệ vào DB của **bản sao** ngay trước `configtest` ⇒ binary đích báo `creating new headscale: init state: initializing policy manager: parsing …`.

**Giới hạn đã biết:** `RollbackRestore` dùng bước kiểm của restore P3-T11 (registry `d.headscale` — không tới được tenant `suspended`), nên rollback bằng restore của một tenant đang suspended dừng ở `failed_resumable`; restart/upgrade thường của tenant suspended vẫn chạy (registry riêng).

## 4. API, quyền, đợt nâng cấp

| Operation | Quyền | Ghi chú |
|---|---|---|
| `POST /platform/instances/{instanceId}/restart` | `platform.instance:operate` | Không body; `Idempotency-Key`; 202 + `Location` job; restart còn chờ ⇒ trả lại job đó; audit `platform.instance.restart.requested` |
| `POST /platform/instances/{instanceId}/upgrade` | `platform.instance:upgrade` | Body `{"image_digest": "sha256:<64 hex>"}` (tag ⇒ 422); 409: `instance_quarantined`, `instance_not_running`, `no_config_version`, `already_on_target`, `tenant_not_active`, `upgrade_in_progress` (đích khác), `operation_in_progress`; cùng đích ⇒ cùng job |

Lệnh đợt (chạy trong container worker, dùng cấu hình DB của worker):

```
docker compose -p mg-app exec -T worker /usr/local/bin/meshguard admin upgrade-wave --image sha256:<64 hex> \
    --canary <instance uuid> (--instances <uuid>,<uuid>… | --all) [--max-parallel N] [--job-timeout 20m] [--dry-run]
```

Canary chạy một mình; xong mới tới các instance còn lại với tối đa N job chưa kết thúc (1..20); upgrade đầu tiên không thành công (hoặc không enqueue được) ⇒ dừng, không enqueue thêm; instance đã ở đích ⇒ bỏ qua; chạy lại lệnh ⇒ tiếp tục đợt đã dừng. Output: một dòng JSON mỗi sự kiện + báo cáo; exit 0 xong, 1 dừng vì lỗi, 2 sai cú pháp/cấu hình. Không thêm lịch hay queue (đợt là lệnh tay).
