## 2. Thiết kế

### 2.1 Luồng `Enroll` (phương thức B của §7.4, chỉ qua adapter)

1. `reg.ForTenant(ctx, tenantID)` — cách **duy nhất** lấy `Instance` (§13.4 quy tắc 1–2); không đọc SQLite của instance, không gọi CLI.
2. **Bảo đảm user:** `ListUsers(name)`; không có ⇒ `CreateUser{Name, DisplayName}` (không gửi email — §13.4); `conflict` (tạo đồng thời) ⇒ đọc lại bằng `ListUsers`, **không** retry ghi (`CreateUser` không idempotent — §13.4 quy tắc 3). Tên mặc định `mg-e2e-enroll` (quy tắc ID-08 do adapter kiểm).
3. **Phân giải lại** `ListUsers(name)` ngay trước lời gọi ghi dùng ID số của user (§13.4 "Không dùng `headscale_user_id` đã cache cho thao tác ghi"); lệch ⇒ dừng.
4. `CreatePreAuthKey{User, Reusable: false, Ephemeral: false, Expiration: now + TTL}` — **hạn tường minh**, TTL mặc định 10 phút, tối đa 15 phút (§7.4), làm tròn xuống giây; không tag. Lỗi ⇒ không retry; key mà instance có thể đã lưu (cùng user, chưa dùng, cùng hạn) bị expire.
5. **Đọc lại** (`ListPreAuthKeys`): key phải một lần, không ephemeral, không tag, đúng user, đúng hạn (± 2 s), chưa dùng — sai bất kỳ điều nào ⇒ expire key và trả lỗi.

### 2.2 Key chỉ tới người gọi

- `Enrollment.Key()` trả `headscale.Secret` (mọi verb `fmt`, `slog`, JSON in `[REDACTED]`); `Enrollment` tự có `Format`/`LogValue` — vì `fmt` in trường **không export** của struct mà không gọi method của chúng, thiếu hai method này `%+v` của một `Enrollment` sẽ in key (test `TestKeyNeverPrinted` khóa lại).
- `WriteKeyFile(dir)`: tạo `dir` 0700 nếu chưa có, file mới bằng `os.CreateTemp` (`O_EXCL`, mode 0600), không xuống dòng cuối — dùng cho `TS_AUTHKEY=file:…` / `tailscale up --auth-key=file:…`. `RemoveKeyFiles` (cũng do `Cleanup` gọi) xóa mọi file đã ghi. `State` chỉ giữ định danh công khai (ID user/key, prefix công khai, hạn, đường dẫn file).
- Helper không ghi log; adapter ghi log qua `logx` (đã che) — `TestEnrollE2E` kiểm log của adapter và file state không chứa key.

### 2.3 Build tag

`mgtestfixture` — tag test-only sẵn có của repo (fixture phiên P2-T15a), không thêm tag mới vì: CI đã `go vet`/`go test -race`/golangci-lint `./tests/...` với tag này (`.golangci.yml` `build-tags`), `internal/archtest` đã cấm tag này ngoài `tests/` và chứng minh `apps/api`/`apps/worker` không phụ thuộc package nào dưới `tests/` (có hoặc không tag); test mới `TestE2EHelpersNeedTheTag` thêm: không tag thì package không có file Go nào. Một tag riêng sẽ cần sửa `go.yml`, `.golangci.yml`, `Makefile` mà không thêm bảo đảm nào.

### 2.4 P3-T14 dùng helper thế nào (tenant C)

P3-T14 (G3) tạo tenant C qua API/orchestrator; registry phải là registry **của worker** (Locator thật: `tenant_instances` + SecretStore + listener admin của edge):

```go
// như phần nối của worker (doc của internal/headscale/locator): store + SecretStore + listener admin của edge
loc, _ := locator.New(tenants.New(st, tenants.Options{BaseDomain: baseDomain}), secretStore,
	locator.Options{AdminURL: edgeAdminURL, EdgeTokenFile: edgeAdminTokenFile})
reg := headscale.NewRegistry(loc, headscale.Options{Logger: logx.New(w, slog.LevelInfo, "e2e")})
e := helpers.EnrollT(t, reg, tenantC, helpers.Options{User: "mg-e2e-enroll"}) // t.Cleanup: expire key, xóa node + user
path, _ := e.WriteKeyFile(keyDir)            // mount vào client: TS_AUTHKEY=file:/run/secrets/authkey
// … khởi động client, chờ e.Nodes(ctx, reg) có node của client …
_ = e.RemoveKeyFiles()
// … áp fixture allow (P3-T08a) → TCP thông → suspend ⇒ chặn → resume ⇒ thông → deprovision …
```

Khi test chạy ngoài tiến trình có PostgreSQL/SecretStore (như stack dev/CI hiện nay), dùng `headscale.StaticLocator` với API key ngắn hạn của instance — đúng cách `TestEnrollE2E` làm (mục 3.2). Runner nhiều tiến trình (container client khởi động giữa hai pha) dùng `State`/`Resume`.
