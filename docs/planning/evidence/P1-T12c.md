Trên host **không** nạp `br_netfilter` (`net.bridge.bridge-nf-call-iptables` không tồn tại) ⇒ lưu lượng giữa các container trên cùng một bridge không đi qua chain IPv4 của host.

## Biện pháp

Bảng nftables họ **`bridge`** trên host (thêm vào [mg-staging-firewall.nft](../../../infrastructure/host/mg-staging-firewall.nft), áp bằng [apply-firewall.sh](../../../infrastructure/host/apply-firewall.sh) — hẹn giờ tự hoàn tác 180 s, xác nhận từ phiên SSH mới; rollback và `ExecStop` nay xóa cả hai bảng; bản trước: `/etc/meshguard/host-firewall.nft.before-p1-t12c`):

```nft
table bridge mg_bridge {
    chain forward {
        type filter hook forward priority filter; policy accept;
        ether type ip ip saddr 10.250.0.0/16 ip daddr != 10.250.0.0/16 counter drop
    }
}
```

Khung IPv4 xuất phát từ pool tenant chỉ được tới địa chỉ trong pool tenant. Lưu lượng edge ↔ Headscale (hai đầu cùng /29 của tenant) không bị ảnh hưởng: `health_probe.py` ngay sau khi áp — `tenant-a key=200 derp=200`, `tenant-b key=200 derp=200`.

## Ghi chú

- `/debug/policy` trả 403 cho nguồn private của Docker — khớp PL-15 (`/debug/*` chỉ nhận loopback hoặc dải Tailscale; riêng `/debug/statsviz` nhận thêm dải private). Edge không bao giờ proxy `/debug/*` ([P1-T10](P1-T10.md)).
- Rule bridge áp cho **mọi** bridge của host; pool tenant `10.250.0.0/16` chỉ dùng cho network tenant (`versions.lock [ids]`). Network tenant mới (Orchestrator — Phase 3) được bảo vệ ngay, không cần thêm rule.
- Cần đưa rule này vào hardening chuẩn của host (§14.1, P6-T07) và vào runbook dựng lại host (P1-T19).
