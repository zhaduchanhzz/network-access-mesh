## 3. V-27 — client chính thức liên lạc host nào của Tailscale Inc. khi dùng Headscale (Linux)

**Cách làm.** Trên b1, một node tạm `x1` (`tailscaled` 1.104.7 userspace dưới user thường, state mới mỗi lượt) đăng
nhập tenant thử P `p5p-44a3` bằng pre-auth key. [capture.py](P5-lab/capture.py): `tcpdump -i any` lọc DNS (53), TCP
80/443, UDP 3478/41641; lấy mẫu `/proc/net/{tcp,udp}` mỗi 0,2 s để gán **UID** cho cổng nguồn ⇒ tách node tạm (uid
1000) khỏi `tailscaled` hệ thống (root), `systemd-resolved` (uid 991, truy vấn lên resolver 192.168.1.1) và nền. Truy vấn
DNS từ socket sống quá ngắn để lấy mẫu ghi là `?` — gán theo thời gian (không có ở nền S0). Chỉ lưu tên truy vấn, SNI,
đích — không lưu payload; pcap xóa sau khi phân tích.

| Tình huống | Mặc định | `TS_NO_LOGS_NO_SUPPORT=true` |
|---|---|---|
| **S0 nền** (không có node tạm, 45 s) | không có luồng mới nào (luồng control/DERP của `tailscaled` hệ thống là kết nối dài sẵn có) | — |
| **S1** khởi động, chưa đăng nhập (50 s) | DNS **`log.tailscale.com`** (qua stub 127.0.0.53 → 192.168.1.1); không có kết nối TCP/TLS | **không có gì** |
| **S2** đăng nhập + map đầy đủ (75 s) | DNS `controlplane.tailscale.com`, `login.tailscale.com`, `<slug>.mesh.<domain>`; TLS **chỉ** tới `<slug>.mesh.<domain>` (`<vps>`:443); STUN `<vps>`:3478; TCP 80 tới `<vps>` | DNS `controlplane.tailscale.com`, `login.tailscale.com`, `<slug>.mesh.<domain>`; TLS chỉ tới `<slug>.mesh.<domain>`; STUN + TCP 80 tới `<vps>` |
| **S3** STUN bị chặn (chỉ TCP 443) | **không chạy** — cần đổi firewall trên VM/mạng (ngoài phạm vi được duyệt) ⇒ ngoại lệ | — |
| **S4** DNS hệ thống lỗi (node đã đăng nhập; `/etc/resolv.conf` → `127.0.0.9` chỉ trong mount namespace của tiến trình — `unshare -m` + `setpriv`, không đổi hệ thống) | DNS thất bại cho `controlplane`/`login`/`log.tailscale.com`, `<slug>.mesh…`; **TLS tới `derp8c.tailscale.com`** (IP cứng của Tailscale — DNS fallback) + TLS tới `<slug>.mesh.<domain>` (`<vps>`, từ map đã lưu); node vẫn `Running` | DNS thất bại như bên trái; **không** liên lạc host nào của Tailscale Inc.; chỉ `<vps>` (443, 80, 3478); vẫn `Running` |

**Danh sách host cho thông báo quyền riêng tư (§15.5) — Linux 1.104.7, đo 2026-11-20:**

- Luôn có (cả khi `TS_NO_LOGS_NO_SUPPORT=true`): **truy vấn DNS** cho `controlplane.tailscale.com` và
  `login.tailscale.com` (lộ tới resolver DNS của khách; không thấy kết nối TCP/TLS nào tới hai host này).
- Chỉ khi **không** đặt `TS_NO_LOGS_NO_SUPPORT`: DNS `log.tailscale.com` ngay từ lúc khởi động (log chẩn đoán — trong
  cửa sổ 50–75 s chưa thấy phiên TLS upload); khi DNS hệ thống lỗi: TLS tới **`derp*.tailscale.com`** (DNS fallback qua
  IP cứng — hostname cần phân giải được gửi cho Tailscale Inc.).
- Với `TS_NO_LOGS_NO_SUPPORT=true`: không có kết nối nào tới host của Tailscale Inc. ở S1, S2, S4.
- Chưa đo: S3 (mạng chỉ TCP 443 — dò captive portal), `tailscale netcheck` khi chưa có map (đã thấy ở VM 105 khi
  `NeedsLogin`: dùng DERP map của Tailscale Inc. — [P5-T02](P5-T02.md) mục 2), các OS khác.
