## 1. Sơ đồ mạng

```text
                         Internet (ISP của LAN — IP công khai a.b.c.x, NAT của router nhà)
                                   │                      ▲
      DNS công khai *.mesh.<domain>│                      │ STUN UDP 3478 + DERP TCP 443 của MỌI client
      app./auth./admin. → <vps>    ▼                      │ (derp.server.ipv4 = <vps> thay DNS — §10.1)
                     ┌──────── VPS (<vps>) ────────┐       │
                     │ l4proxy TCP 80/443 (PROXY v2)│◄──────┘
                     │ stund UDP 3478               │
                     └──────────────┬───────────────┘
                                    │ WireGuard site-to-site (host LAN chủ động nối)
LAN 192.168.1.0/24 (vmbr0)          ▼
  VM 104 mg-staging ── edge (listener tunnel-facing + LAN-direct) ── Headscale tenant-a / tenant-b / tenant thử
  VM 106 mg-client-a1  lab-a1  tenant-a  control qua DNS công khai → VPS → tunnel → edge
  VM 107 mg-client-b1  lab-b1  tenant-b  control qua DNS công khai → VPS → tunnel → edge
  VM 105 mg-ci-runner  (client thứ năm — chưa đăng nhập; container client chính thức cho tenant thử)
  OPNsense (VM 100) ── NAT ──┐
segment lan10 192.168.10.0/24 │ (nguồn bị đổi IP + cổng)
  VM 108 mg-client-a2  lab-a2  tenant-a  control qua /etc/hosts → edge LAN-direct; ÉP RELAY thường trực
  VM 109 mg-client-b2  lab-b2  tenant-b  control qua /etc/hosts → edge LAN-direct; ÉP RELAY thường trực
```

Mọi client đi STUN và DERP tới `<vps>` (IP trong DERP map — client không tra DNS cho DERP/STUN, §10.1), kể cả client
trong LAN: đường relay luôn vòng qua VPS + tunnel (RTT relay ~91–93 ms, mục 3), đường trực tiếp đi thẳng trong LAN
qua NAT của OPNsense (1 ms).

## 3. Đường đi + TCP thật (`p5lab.py paths`, 02:33–02:40 UTC; fixture `test-allow-intra`: TCP 8000 + ICMP)

Listener tạm (`collect.sh listen`, python3, nền) trên cổng 8000 (trong grant) và 8001 (ngoài grant) ở cả 4 client; gỡ
ngay sau phép thử.

| Hướng | `tailscale ping --until-direct=false` | TCP 8000 (grant) | TCP 8001 (ngoài grant) | Kết quả |
|---|---|---|---|---|
| a1 → a2 | `via DERP(mg-tenant-a)` 92 ms | OPEN, connect 191 ms, banner `p5lab mg-client-a2` | timeout 5,0 s | đạt |
| a2 → a1 | `via DERP(mg-tenant-a)` 92 ms | OPEN, connect 96 ms | timeout 5,0 s | đạt |
| b1 → b2 | `via DERP(mg-tenant-b)` 93 ms | OPEN, connect 199 ms | timeout 5,0 s | đạt |
| b2 → b1 | `via DERP(mg-tenant-b)` 91 ms | OPEN, connect 97 ms | timeout 5,0 s | đạt |

Vì a2/b2 ép relay thường trực, mọi cặp cùng tenant đi qua relay **của đúng tenant** (`DERP(mg-tenant-<x>)`).

## 4. Phương pháp ép relay (§9.5) — kiểm hai chiều trên a2 (`p5lab.py relaydemo a2`, 02:47–02:50 UTC)

Cách dùng cho P5-T04…T07: `collect.sh relay on` (thêm `TS_DEBUG_ALWAYS_USE_DERP=true`), `relay direct` (bỏ dòng đó),
`relay off` (trả lại đúng file gốc từ bản sao `/etc/default/tailscaled.p5lab-orig`); mỗi lần đổi restart `tailscaled`
và in giá trị trong file **và** trong môi trường thật của tiến trình. Phương án thay thế (§9.5) — chặn UDP giữa hai mạng
— cần đổi firewall/OPNsense nên **không** dùng.

| Bước | Môi trường `tailscaled` của a2 | a2 → a1 `tailscale ping` | TCP 8000 |
|---|---|---|---|
| Ban đầu | file 1 dòng, tiến trình `TS_DEBUG_ALWAYS_USE_DERP=true` | `via DERP(mg-tenant-a)` 91 ms | OPEN, connect 192 ms |
| `relay direct` | file 0, tiến trình không có | `via 192.168.1.21:41641` **1 ms** (direct qua NAT của OPNsense) | OPEN, connect 101 ms (gói đầu qua DERP trước khi nâng direct — CL-06) |
| `relay off` (trả lại) | file 1, tiến trình có | `via DERP(mg-tenant-a)` 91 ms | — |

Trạng thái cuối = trạng thái ban đầu (so khớp output `relay status`); bản sao `.p5lab-orig` đã xóa. Đây là thay đổi duy
nhất lên cấu hình Tailscale của client lab trong task, đã hoàn tác (hai lần chạy — lần đầu mất output `ping` vì SSH qua
ProxyCommand bị ngắt; script đã thêm thử lại cho lỗi kết nối SSH).

| [p5lab.py](P5-lab/p5lab.py) | Máy vận hành | Đẩy `collect.sh` (`cat >` + kiểm md5, lệnh SSH riêng), chạy, kéo về và **che** (IP công khai ⇒ `<vps>` / `a.b.c.x`, domain ⇒ `<domain>`, `hskey-…`); bước `inventory`, `paths`, `relaydemo`, `ac20`, `v02`, `provision`, `t05`, `t05a`, `cleanup`. ## 6. Đối chiếu tiêu chí + ngoại lệ

| Tiêu chí P5-T02 | Kết quả |
|---|---|
| ≥ 4 thiết bị thật | **Đạt** — 4 VM client (+ VM 105 làm client thứ năm/máy container), đều là máy riêng, khác host Headscale |
| ≥ 2 hệ điều hành | **Ngoại lệ chờ thiết bị** — chỉ Linux (Ubuntu 24.04.5). Chủ dự án duyệt Phase 5 chỉ dùng VM lab (2026-11-20); Windows/macOS/iOS/Android (V-07 phần còn lại, V-08, ma trận P5-T03) chạy khi có thiết bị |
| ≥ 2 mạng, ≥ 1 mạng ngoài LAN đi qua VPS | **Đạt ở chế độ LAN NAT** — mạng 1: LAN `vmbr0` (a1, b1: control qua DNS công khai → VPS → tunnel); mạng 2: segment `lan10` sau NAT của OPNsense (a2, b2). STUN + DERP của **mọi** client đi qua VPS. **Ngoại lệ**: không có thiết bị ở mạng ngoài LAN thật (4G, mạng khác ISP) — phần "từ Internet" của AC-20/V-02 chạy từ máy vận hành và client lab đi ra Internet ([P5-T02a](P5-T02a.md)) |
| Phương pháp ép relay | **Đạt** — `TS_DEBUG_ALWAYS_USE_DERP` bật/tắt/trả lại có kiểm môi trường tiến trình (mục 4) |
| Sơ đồ mạng + danh sách thiết bị/phiên bản | **Đạt** — mục 1, 2 |
| Script chạy được trên từng thiết bị | **Đạt** — mục 5 |
