## Thiết kế

### Đường vào duy nhất và `Locator` (việc của P2-T11)

`Registry.ForTenant(ctx, tenantID)` là cách **duy nhất** lấy `Instance`; không hàm nào nhận URL hay địa chỉ từ input (§13.4 quy tắc 1). `CachingRegistry` dựng trên interface `Locator` mà lead hiện thực ở P2-T11 (đọc `tenant_instances` + SecretStore):

```go
type Locator interface {
    Locate(ctx context.Context, tenantID uuid.UUID) (Target, error) // lỗi bọc ErrNoInstance khi tenant không có instance chạy được
}
type Target struct {
    InstanceID uuid.UUID     // khóa của breaker, có trong log
    Slug       string        // X-MG-Instance (regex slug §14.5)
    AdminURL   string        // http(s)://host:port của listener admin edge, không path/query/userinfo
    APIKey     Secret        // API key của instance
    EdgeToken  Secret        // token của listener admin (40 ký tự [A-Za-z0-9])
    Timeout    time.Duration // timeout riêng của instance; 0 = Options.Timeout
}
```

`Locate` được gọi khi cache trượt, khi hết `CacheTTL` (mặc định 60 s) và — bỏ qua cache — khi edge trả 403 hoặc Headscale trả 401; nếu credential đổi (vừa xoay key) request được phát lại **một** lần (request bị từ chối ở tầng xác thực chưa được xử lý nên phát lại an toàn cả với lệnh ghi). Key vẫn bị từ chối sau khi nạp lại ⇒ `api_key_rejected` + log mức error "nghi DB của instance đã bị thay" (§13.4); cảnh báo Critical là việc của bên gọi, adapter **không** chạy lại `apikey.bootstrap`. Locator trả `Target` không hợp lệ ⇒ `internal`. `StaticLocator` (bảng cố định) dùng cho test và phát triển cục bộ.

### Header scheme qua listener admin (§14.6)

Mọi request: `X-MG-Token: <token listener>`, `X-MG-Instance: <slug>`; `/api/v1/*` thêm `Authorization: Bearer <API key instance>`; `GET /version` **không** gửi API key (Headscale không cần). URL = `AdminURL` đã kiểm + path hằng; segment biến (id, tên mới) đã kiểm định dạng và `url.PathEscape`. Client HTTP mặc định không lấy proxy từ biến môi trường và không theo redirect (Go chuyển tiếp header tùy biến như `X-MG-Token` sang host khác). Hành vi thật của Caddy 2.11.9 với khối admin của `Caddyfile.tmpl` được ghim ở P2-T10.

### Ánh xạ lỗi

REST gateway trả HTTP 500 cho phần lớn lỗi nghiệp vụ, nên `classify` đọc thân `{code, message}` của grpc-gateway, rồi luật riêng từng operation, rồi mẫu thông điệp. Thông điệp gốc (đã che credential) chỉ nằm trong `Error.Upstream` để ghi log nội bộ; `Error.Detail()` là câu lọc sẵn cho `Problem.detail`.

| Kind | `Problem.code` | Ví dụ thân lỗi 0.29.7 (quan sát ở P2-T10) |
|---|---|---|
| `validation` | `validation_failed` (422) | tag/tên/route sai, `400 code 3`; Auth ID không chờ: `500 code 2 "node not found in registration cache"`, `404 code 5 "no pending auth session…"` (§13.4: Auth ID ⇒ validation, không phải 404) |
| `not_found` | `not_found` | `404 code 5 "node not found"`; `500 code 2 "user not found"`, `"node no longer exists in NodeStore: <id>"` (kể cả khi bọc trong `400 code 3` của `SetApprovedRoutes`), `"record not found"` |
| `conflict` | `conflict` | `500 code 13 "…UNIQUE constraint failed: users.name"`, `"user not empty: node(s) found"`, `"node name is not unique"`, `"cannot edit OIDC user"` |
| `policy_rejected` | `upstream_rejected` (502) | `CheckPolicy` `400 code 3`; `SetPolicy` `500 code 2 "setting policy: …"` (outcome `not_applied`) hoặc lỗi khác sau hoán đổi (outcome `unknown`, V-26) |
| `no_policy` | `upstream_rejected` | `500 code 2 "…acl policy not found"` hoặc policy lưu là chuỗi rỗng (PL-06) — job drift xử lý là Critical |
| `upstream_rejected` | `upstream_rejected` | `404 code 5 "Not Found"` (route không có trên version này), thân 2xx không đọc được, redirect, mã khác |
| `unavailable` | `instance_unavailable` (503) | lỗi truyền tải, timeout, 503/504, **404/502 rỗng của edge** (edge biến lỗi dial thành 404 qua `handle_errors`), lỗi lưu trữ (`"database or disk is full"`, `"database is locked"`) |
| `circuit_open` | `instance_unavailable` | breaker mở — không gọi |
| `api_key_rejected` | `instance_unavailable` | `401 "Unauthorized"` (văn bản thường) sau khi đã nạp lại key |
| `edge_rejected` | `instance_unavailable` | `403` rỗng của edge (token sai — lỗi cấu hình nền tảng) |
| `unsupported_version` | `instance_unavailable` | `/version` ngoài dải hỗ trợ hoặc không phải bản release |
| `internal` | `internal_error` | Target/Locator lỗi |

`Outcome` của lệnh ghi: `unknown` khi request đã đi mà câu trả lời mất (đứt kết nối, timeout, 404/502/504 rỗng của edge — instance có thể chết giữa chừng, đúng như V-26 quan sát) hoặc khi `SetPolicy` lỗi **sau** khi Headscale đã hoán đổi policy trong bộ nhớ; `not_applied` khi bị từ chối trước (hoặc lỗi dial — chưa gửi).

### Breaker, timeout, retry

- **Breaker theo instance** (khóa `InstanceID`, mặc định mở sau 5 lỗi liên tiếp, mở 30 s rồi cho một lần thử): chỉ đếm lỗi truyền tải, timeout của chính adapter, 503/504 và câu "không route được" của edge (404/502 rỗng). Mọi câu trả lời khác — kể cả `not_found` hay lỗi lưu trữ 500 — chứng tỏ instance còn sống và đặt lại bộ đếm (§13.4). Request bị **bên gọi** hủy không tính.
- **Timeout** theo lần gọi (mặc định 10 s, `Target.Timeout` ghi đè theo instance).
- **Retry**: chỉ GET an toàn (`Op.RetryClass() == RetrySafe`), tối đa 3 lần, backoff mũ có jitter (200 ms → 2 s), dừng khi breaker mở hoặc context hết. `RetryIdempotentWrite` (`SetPolicy`, `ExpireNode` với thời điểm tường minh, `SetApprovedRoutes`, `SetTags`, `ExpirePreAuthKey`, `DeleteNode`, …) **không** retry trong adapter — job layer retry có backoff (§13.5); `RetryNever` (`CreateUser`, `CreatePreAuthKey`, `CreateAPIKey`, `AuthRegister`) không bao giờ phát lại, đối soát bằng đọc lại.

### Lớp version (RT-11)

`ForTenant` đọc `GET /version` (qua edge), chấp nhận đúng bản release `vX.Y.Z` trong dải của một implementation (hiện có `rest-v1/0.29`: `>= 0.29.7, < 0.30.0` — sàn 0.29.7 vì ID-09), cache cùng target. 0.30 (bỏ gRPC, REST v1 mới với lỗi RFC 7807, API v2) sẽ là một mục mới của `apiImpls`; nâng cấp được phát hiện khi cache hết hạn hoặc sau `Invalidate`.

### Kiểm tra cục bộ trước khi gọi (không gọi Headscale nếu sai)

Auth ID `^hskey-authreq-[A-Za-z0-9_-]{24}$`; tên user theo ID-08 (REST không kiểm — P2-T10 tạo được user tên `1 bad/name`); tên node là một nhãn DNS chữ thường; tag `tag:[a-z][a-z0-9-]{0,62}`; route phải chuẩn tắc; `SetTags([])` bị chặn (V-28); `CreatePreAuthKey`/`CreateAPIKey` bắt buộc `expiration` tương lai (V-06); `ExpireNode` luôn gửi thời điểm tường minh ở **query string** (`at == nil` ⇒ "bây giờ" theo đồng hồ nền tảng); `SetPolicy` luôn chạy `CheckPolicy` trước; tài liệu policy qua `ValidatePolicyDocument`: không rỗng (PL-06), JSON thuần, không khóa bắt đầu bằng `#` ở mọi mức, khóa top-level đúng 11 tên với đúng kiểu chữ, không khóa trùng (so không phân biệt hoa thường), `grants` bắt buộc và là mảng (không `null`).

### Credential và log

API key mới (`CreateAPIKey`) và pre-auth key (`PreAuthKey.Key`) trả về dạng `Secret`; `Target` mang `APIKey`/`EdgeToken` dạng `Secret`. Adapter không log header hay body; log mỗi lần gọi (debug: op, tenant, instance, method, path, attempt, thời gian; lỗi: kind, status, code, outcome, thông điệp đã che) — logger nên dựng bằng `logx.New`. Thông điệp upstream được thay đúng giá trị API key/edge token và mọi chuỗi `hskey-…` trước khi lưu vào `Error`.
