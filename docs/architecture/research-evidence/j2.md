# Research Evidence — J2

> Một phần của [nhật ký bằng chứng nghiên cứu](../research-evidence.md) (P0-T08). Chép nguyên từ kết quả của research agent ngày 2026-11-16; nhận định và trích dẫn giữ nguyên tiếng Anh.

## J2 - Technology stack validation for the management plane (versions, licences, maturity, fit) as of 2026-11-16

**Tóm tắt của agent:** Every candidate component was checked against primary sources on 2026-11-16: the Go module proxy, the npm registry, GitHub release redirects, tagged READMEs and licence files, and official documentation. The proposed stack is viable with current, mostly permissively licensed releases, but several facts differ from older knowledge and should change the design. Backend: Go 1.27.4 is current. net/http ServeMux patterns are enough for routing, paired with the oapi-codegen v2.8.2 strict server. Use pgx v5.13 with sqlc v1.31 and goose v3.30; Atlas's Apache-2.0 build lacks RLS support. River v0.51 gives transactional enqueue, unique jobs and backoff retries, but it is pre-1.0 and its open-source periodic jobs are not durable. The Docker Go SDK moved to github.com/moby/moby/client, and github.com/docker/docker is frozen. Compose v5 has an official Go SDK that pulls in docker/cli, so calling the `docker compose` CLI with explicit project names is the lower-risk default. Frontend: React 19.3, Vite 8 (Rolldown), React Router 8 (ESM-only, Node 22.22+), TanStack Query 5, openapi-typescript with openapi-fetch, Tailwind 4, and shadcn on Radix or React Aria are all current. Pin TypeScript: npm's latest is 7.0.2, while the OpenAPI generator and typescript-eslint support only 5.x/6.0. CLDR 49 changed Vietnamese plural categories, so Vietnamese catalogs need care. Identity: only Keycloak 26.8 (Apache-2.0; realm per tenant, or Organizations inside one realm) and Zitadel v4 (AGPL-3.0 since v3; one virtual instance per issuer) offer a per-tenant issuer in one open-source deployment. Keycloak needs about 1.25 GB per instance, and its realm-count scaling is unproven and must be load-tested. authentik tenancy is enterprise-only and alpha. Kanidm, Pocket ID, Dex and Authelia are single-issuer. Secrets and backup: Compose file secrets are plain bind mounts whose uid/gid/mode settings are ignored. Use SOPS with age at rest plus application-level envelope encryption, with OpenBao 2.7 (MPL-2.0) as a later key provider; Vault is BUSL. Back up SQLite with VACUUM INTO or the backup API, never a raw file copy. Litestream 0.5 is beta and adds a table to the source database. PostgreSQL 18.7 is current and 19 is still RC 2; use pgBackRest 2.59.3 or later for point-in-time recovery. Host and operations: Promtail is end of life, so use Alloy. Docker-published ports bypass ufw. Rootless Docker does not propagate UDP source addresses, which is a likely blocker for per-tenant STUN and needs a test. Socket proxies filter by method and path and are not a sandbox. Trivy's March 2026 compromise means scanners and CI actions must be pinned by digest or commit SHA. Docker Engine 29.9 supports Ubuntu 22.04, 24.04 and 26.04 LTS.

## Nhận định

### J2-A01 · `VERIFIED` — Go toolchain

- **Nhận định:** Go 1.27.4 (released 2026-11-10) is the current stable toolchain; Go 1.27.0 shipped 2026-08-19 and only the two newest majors (1.27.x and 1.26.x, currently 1.26.11) receive fixes.
- **Bằng chứng:** go.dev/dl JSON lists go1.27.4 and go1.26.11 as stable; release page: 'go1.27.4 (released 2026-11-10)'; 'Each major Go release is supported until there are two newer major releases.'
- **Nguồn:** https://go.dev/doc/devel/release ; https://go.dev/dl/?mode=json

### J2-A02 · `VERIFIED` — HTTP routing: net/http ServeMux vs chi

- **Nhận định:** Since Go 1.22 net/http ServeMux patterns match method, host and {wildcard} or {rest...} path segments with most-specific-wins precedence and panic on conflicting registrations; chi v5.5.0 (MIT) adds middleware stacks, route groups, sub-router mounting and regex parameters while staying net/http-compatible.
- **Bằng chứng:** server.go: '[METHOD ][HOST]/[PATH]'; 'The pattern syntax and matching behavior of ServeMux changed significantly in Go 1.22'. chi README: '100% compatible with net/http ... middlewares, inline middlewares, route groups and sub-router mounting'.
- **Nguồn:** https://raw.githubusercontent.com/golang/go/go1.27.4/src/net/http/server.go (lines 2532-2650) ; https://raw.githubusercontent.com/go-chi/chi/v5.5.0/README.md

### J2-A03 · `VERIFIED` — pgx v5 and sqlc

- **Nhận định:** pgx v5.13.0 (MIT, 2026-11-11) is a pure-Go PostgreSQL driver with pgxpool (after-connect hook), LISTEN/NOTIFY, COPY and tracing, supporting PostgreSQL 14 and higher; sqlc v1.31.1 (MIT, 2026-04-22) generates pgx/v5 code and rates Go with PostgreSQL as Stable.
- **Bằng chứng:** pgx README: 'This means pgx supports Go 1.25 and higher and PostgreSQL 14 and higher.' sqlc docs: '`pgx/v5` is supported starting from v1.18.0'; language table: Go (built-in) PostgreSQL 'Stable'.
- **Nguồn:** https://raw.githubusercontent.com/jackc/pgx/v5.13.0/README.md ; https://raw.githubusercontent.com/sqlc-dev/sqlc/v1.31.1/docs/guides/using-go-and-pgx.rst ; https://raw.githubusercontent.com/sqlc-dev/sqlc/v1.31.1/docs/reference/language-support.rst

### J2-A04 · `VERIFIED` — Migrations: goose vs golang-migrate

- **Nhận định:** goose v3.30.1 (MIT) supports SQL and Go migrations, embed.FS, out-of-order application and a per-file '-- +goose NO TRANSACTION' marker; golang-migrate v4.20.1 (MIT) has a pgx/v5 driver, uses pg_advisory_lock, and leaves a dirty version that must be forced manually after a failed migration.
- **Bằng chứng:** goose README: 'Supports Go migrations written as plain functions. Supports embedded migrations. Out-of-order migrations.' migrate FAQ: 'the dirty state persists ... You need to manually fix the error and then "force" the expected version.'
- **Nguồn:** https://raw.githubusercontent.com/pressly/goose/v3.30.1/README.md ; https://raw.githubusercontent.com/golang-migrate/migrate/v4.20.1/FAQ.md ; https://raw.githubusercontent.com/golang-migrate/migrate/v4.20.1/database/pgx/v5/README.md

### J2-A05 · `UNSUPPORTED` — Migrations: Atlas

- **Nhận định:** Atlas v1.3.0's Apache-2.0 Community Edition does not support row-level security, views, triggers, functions or migration linting; those need the standard binary, which is distributed under the Atlas MSA rather than an open-source licence.
- **Bằng chứng:** 'The Community Edition is built directly from the Atlas GitHub repository and is licensed under the Apache 2.0 license'; unsupported list includes 'Row-level security (RLS)'; standard binary is under 'the terms of the Atlas MSA'.
- **Nguồn:** https://atlasgo.io/community-edition ; https://raw.githubusercontent.com/ariga/atlas/v1.3.0/LICENSE

### J2-A06 · `VERIFIED` · *critical* — River job queue core

- **Nhận định:** River v0.51.2 (MPL-2.0, 2026-11-09) is a Postgres- or SQLite-backed Go job queue with transactional enqueue (Client.InsertTx on pgx v5), unique jobs by args, period, queue and state, and retries with attempt^4 backoff up to a default of 25 attempts.
- **Bằng chứng:** README: 'Jobs are guaranteed to be enqueued if their transaction commits, are removed if their transaction rolls back'. retry_policy.go: 'basic exponential backoff of `ATTEMPT^4`'. client.go: 'defaults to 25 (MaxAttemptsDefault)'.
- **Nguồn:** https://raw.githubusercontent.com/riverqueue/river/v0.51.2/docs/README.md ; https://raw.githubusercontent.com/riverqueue/river/v0.51.2/retry_policy.go ; https://raw.githubusercontent.com/riverqueue/river/v0.51.2/insert_opts.go ; https://raw.githubusercontent.com/riverqueue/river/v0.51.2/client.go

### J2-A07 · `VERIFIED` — River periodic jobs, Pro tier and UI

- **Nhận định:** Open-source River periodic jobs are scheduled in memory by the elected leader and are not durable; durable periodic jobs, workflows, sequences and concurrency limits are paid River Pro features; River UI v0.22.0 (MPL-2.0) embeds as an http.Handler with only HTTP basic auth built in.
- **Bằng chứng:** periodic_job.go: 'The periodic job scheduler is approximate and doesn't guarantee strong durability ... each scheduler only retains in-memory state'. riverqueue.com/pro lists 'Durable periodic jobs', 'Workflows', 'Concurrency limits'. riverui README: 'RIVER_BASIC_AUTH_USER'.
- **Nguồn:** https://raw.githubusercontent.com/riverqueue/river/v0.51.2/periodic_job.go ; https://riverqueue.com/pro ; https://raw.githubusercontent.com/riverqueue/riverui/v0.22.0/docs/README.md

### J2-A11 · `VERIFIED` — Authorisation: Casbin

- **Nhận định:** Casbin v3.10.0 (Apache-2.0; the v2 line is at v2.135.0) is an in-process authorization library driven by a PERM model file that supports ACL, RBAC, RBAC with domains/tenants and ABAC; it does not authenticate users or manage user and role lists.

### J2-A12 · `VERIFIED` — Authorisation: OpenFGA and Cedar

- **Nhận định:** OpenFGA v1.22.1 (Apache-2.0) is a separate Zanzibar-style server needing PostgreSQL 14+ or MySQL 8 (SQLite beta, in-memory for development only); cedar-go v1.9.2 (Apache-2.0) embeds in-process but lacks policy templates, partial evaluation and a non-experimental schema validator.
- **Bằng chứng:** OpenFGA README: 'Supported storage: PostgreSQL 14+, MySQL 8, SQLite (beta)'. cedar-go README: 'does not yet include: ... the schema validator (experimental support ...) ... partial evaluation ... support for policy templates'.

### J2-A13 · `ASSUMED` — Authorisation approach (pros and cons)

- **Nhận định:** For a fixed platform and tenant role matrix, a hand-rolled role-permission table checked in the Go service layer plus PostgreSQL RLS is sufficient; Casbin adds a policy DSL, and OpenFGA or Cedar add a service or language that only pays off for per-resource sharing or customer-authored policies.
- **Bằng chứng:** Inference from the capability profiles in J2-A11 and J2-A12; no source states this. Hand-rolled: fewest moving parts but correctness is ours to test. Casbin: tenant-domain RBAC ready-made. OpenFGA: extra server and datastore.
- **Nguồn:** Inference from the sources of J2-A11 and J2-A12

### J2-H07 · `VERIFIED` · *critical* — Rootless Docker and published UDP ports

- **Nhận định:** In rootless Docker, RootlessKit's default builtin port driver propagates client source IPs for TCP only (since v3.0, with userland-proxy disabled) and not for UDP, the gvisor-tap-vsock port driver propagates none, and SCTP ports, AppArmor and overlay networks are unsupported.
- **Bằng chứng:** rootlesskit port.md: 'Source IP propagation (`--source-ip-transparent`) applies to TCP only; UDP is not propagated.' Docker docs: 'Port forwarding with `docker run -p` does not propagate source IP addresses by default.'
- **Nguồn:** https://raw.githubusercontent.com/rootless-containers/rootlesskit/v3.3.0/docs/port.md ; https://docs.docker.com/engine/security/rootless/troubleshoot.md

### J2-H08 · `REQUIRES_VALIDATION` · *critical* — Rootless Docker consequence for per-tenant STUN

- **Nhận định:** Because rootless port forwarding hides UDP source addresses, a per-tenant embedded STUN listener published from a rootless daemon would probably report a wrong reflexive address to Tailscale clients; this needs a hands-on check before rootless mode is considered for tenant containers.
- **Bằng chứng:** Test: run Headscale with embedded DERP/STUN under rootless Docker with the builtin and slirp4netns port drivers and compare the reflexive address and port from `tailscale netcheck` against rootful Docker.
- **Nguồn:** Inference from https://raw.githubusercontent.com/rootless-containers/rootlesskit/v3.3.0/docs/port.md

### J2-H09 · `VERIFIED` — userns-remap limitations

- **Nhận định:** A Docker daemon with userns-remap cannot share the host PID or network namespace (--pid=host, --network=host), cannot run --privileged containers unless --userns=host is given, and requires pre-arranged ownership for host-mounted volumes.
- **Bằng chứng:** 'Sharing PID or NET namespaces with the host (`--pid=host` or `--network=host`).' 'Using the `--privileged` mode flag on `docker run` without also specifying `--userns=host`.'
- **Nguồn:** https://docs.docker.com/engine/security/userns-remap.md

### J2-H10 · `VERIFIED` · *critical* — Docker published ports bypass ufw

- **Nhận định:** Ports published by Docker bypass ufw rules on Ubuntu because Docker diverts container traffic in the nat table before it reaches the INPUT and OUTPUT chains that ufw manages.
- **Bằng chứng:** 'Docker and ufw use firewall rules in ways that make them incompatible with each other.' 'packets are diverted before it reaches the `INPUT` and `OUTPUT` chains that ufw uses.'
- **Nguồn:** https://docs.docker.com/engine/network/packet-filtering-firewalls.md

### J2-H11 · `VERIFIED` — Ubuntu LTS releases currently supported

- **Nhận định:** Ubuntu LTS releases in standard security maintenance are 22.04 (until May 2027), 24.04 (until May 2029) and 26.04 (released April 2026, until May 2031); Docker Engine packages target 22.04, 24.04, 26.04 and the interim 26.10.
- **Bằng chứng:** ubuntu.com: '26.04 LTS Released: Apr 2026 Standard security maintenance May 2031'; '22.04 LTS ... May 2027'. Docker: 'Ubuntu Stonking 26.10, Ubuntu Resolute 26.04 (LTS), Ubuntu Noble 24.04 (LTS), Ubuntu Jammy 22.04 (LTS)'.
- **Nguồn:** https://ubuntu.com/about/release-cycle ; https://docs.docker.com/engine/install/ubuntu.md

## Hệ quả thiết kế (agent đề xuất)

- Go toolchain: pin Go 1.27.x in go.mod and CI, because only 1.27 and 1.26 receive fixes; plan a toolchain bump every six months.
- HTTP and OpenAPI: default to net/http ServeMux with the oapi-codegen v2.8.2 strict std-http server, because it adds no router dependency and gives typed handlers; main alternative is chi v5.5 (if route groups and mounts are wanted) or ogen (own router, built-in OpenTelemetry).
- Data access: default to pgx v5.13 with pgxpool plus sqlc v1.31 (sql_package pgx/v5), because both target PostgreSQL natively; wrap every request in a transaction that calls set_config('app.tenant_id', $1, true). Alternative: hand-written pgx queries.
- Migrations: default to goose v3.30 with embedded SQL migrations, because it is MIT and handles RLS DDL as plain SQL; alternative golang-migrate v4.20 (note its dirty-state manual recovery). Do not rely on Atlas unless its non-open-source binary is acceptable.
- Jobs: default to River v0.51 with InsertTx for provisioning and reconcile work, because enqueue commits atomically with our state; make workers idempotent, set RunOnStart for periodic jobs since OSS scheduling is in-memory, and mount River UI behind portal auth. Alternative: a hand-rolled outbox table with SKIP LOCKED.
- Portal authentication: default to go-oidc v3.21 with x/oauth2 v0.38 (authorization code with PKCE) and server-side sessions in PostgreSQL via scs v2.9 pgxstore; alternative is a small custom session table, since scs has had no tagged release since April 2025.
- Authorisation: default to a hand-rolled role-permission table enforced in the service layer with PostgreSQL RLS (ENABLE plus FORCE, non-owner application role without BYPASSRLS) as defence in depth; alternative Casbin RBAC-with-domains. Adopt OpenFGA only if per-resource sharing becomes a requirement.
- Logging and telemetry: default to log/slog JSON output plus OpenTelemetry-Go v1.47 (all three signals are stable) exported through Alloy; alternative is Prometheus client metrics only for the first release.
- Docker control: default to a narrow deployer component that shells out to docker compose v5.7 with an explicit -p project name per tenant and uses github.com/moby/moby/client only for read-only inspection; alternative is the Compose Go SDK, at the cost of importing docker/cli. Never import github.com/docker/docker.
- Headscale gRPC clients: generate with buf v1.75 using local plugins against protos pinned to the Headscale tag; no Buf Schema Registry account is needed.
- Frontend: default to React 19.3, Vite 8, React Router 8 in Data mode as a static SPA, TanStack Query 5 and openapi-typescript with openapi-fetch, built on Node 24 or 26; alternative is React Router 7.18 (dist-tag version-7) if ESM-only or Node 22.22+ constraints bite. Pin TypeScript to a 5.x release that the generator and linter support.
- UI and i18n: default to shadcn components on Radix (or the aria base for React Aria) with Tailwind 4.3; default i18n to react-i18next 18 for lowest integration risk, alternative Lingui 6 for ICU messages and extraction. Give every Vietnamese plural message both one and other forms because CLDR 49 changed the vi categories.
- Topology view: default to @xyflow/react 12 (MIT); either keep the attribution or budget a Pro subscription. Alternative: a simple table and SVG view for the first release.
- Identity provider: default to Keycloak 26.8 with one platform realm for operators and a realm per tenant where a tenant needs its own issuer, because it is Apache-2.0 with a complete Admin REST API; reserve at least 1.5 GB RAM for it. Alternatives: Keycloak Organizations in one shared realm (single issuer, organization claim) or Zitadel v4 virtual instances (AGPL-3.0-only, legal review needed).
- Secrets: default to SOPS with age for files at rest, Compose file secrets with host-side 0400 ownership (uid, gid and mode are ignored for file sources), and application-level envelope encryption (per-tenant DEK wrapped by a KEK kept outside PostgreSQL) for stored tenant secrets; alternative and later step is OpenBao 2.7 as KEK provider. Avoid Vault for a hosted product because of its BUSL terms.
- SQLite backup: default to a scheduled VACUUM INTO (or .backup) per tenant into a staging path, then age-encrypt and push with restic; never copy the live file. Alternative: Litestream 0.5 for continuous replication, only after validating its _litestream_lock table and WAL handling against Headscale.
- PostgreSQL: default to PostgreSQL 18.x with uuidv7() keys and range-partitioned audit tables (partition key inside the primary key); adopt 19 only after general availability. Back up with pgBackRest 2.60 for PITR plus a nightly pg_dump; alternative WAL-G v3. Keep tenant context transaction-scoped so a later PgBouncer in transaction mode stays safe.
- Observability: default to Prometheus 3.16 (or LTS 3.13 for slower upgrades), Alertmanager 0.35, Grafana 13.3, Loki 3.7 and Alloy 1.22, with cAdvisor, node_exporter and blackbox_exporter; do not deploy Promtail. Write a small custom STUN/DERP probe because blackbox_exporter has no UDP prober. Run Grafana and Loki unmodified to keep AGPL obligations simple.
- Supply chain: default to Syft SBOMs, Grype scanning and cosign signing, with every CI action pinned by commit SHA and every image by digest; alternative scanner is Trivy, pinned the same way given its March 2026 compromise.
- Host: default to rootful Docker Engine 29.9 on Ubuntu 24.04 LTS (26.04 LTS is the alternative), because rootless mode does not propagate UDP source addresses; filter published ports with DOCKER-USER or nftables rules rather than ufw, and expose the Docker API only through wollomatic/socket-proxy to the deployer, treating that deployer as root-equivalent.

## Câu hỏi mở

- How many realms can one Keycloak 26.8 instance carry on the target host before memory, startup or admin latency degrade? Load-test 50, 200 and 500 realms.
- Can a tenant Headscale instance enforce tenant separation with a shared issuer and the Keycloak organization claim, or does each tenant need its own realm and issuer? Depends on Headscale OIDC filtering (other research area).
- Does rootless Docker break STUN reflexive addresses for embedded DERP, and does userns-remap interfere with the tenant container layout? Run tailscale netcheck against both modes.
- Does Litestream 0.5 coexist with Headscale's SQLite usage (WAL mode, the added _litestream_lock table, checkpoints, migrations), and does a restored database start cleanly?
- Under realistic Headscale write load, does the SQLite backup API finish reliably, or is VACUUM INTO the more predictable choice? Measure duration and lock impact per tenant.
- Is River's pre-1.0 API churn and non-durable periodic scheduling acceptable, including behaviour on leader failover? Test with two backend replicas.
- Which TypeScript version should be pinned so that openapi-typescript, typescript-eslint, Vite 8 and the editor agree, and does TypeScript 7 work for type-checking only?
- How do target browsers resolve Intl.PluralRules for Vietnamese given the CLDR 49 change, and how does the chosen i18n library fall back when a 'one' form is missing?
- Does Lingui's macro transform work cleanly with Vite 8, Rolldown and @vitejs/plugin-react 6 if Lingui is preferred over react-i18next?
- What minimal Docker API allowlist does docker compose up/down need through a socket proxy, and can container-create be constrained enough to matter, or should the deployer run on the host instead?
- Is AGPL-3.0 (Zitadel, Grafana, Loki) acceptable to the organisation when the software is run unmodified as separate services? Needs a legal decision.
- Where should the KEK live on a single host before OpenBao is introduced, and what is the rotation and recovery procedure?
- How is pgBackRest best run with a Compose-managed PostgreSQL (shared volume and archive_command versus a sidecar), and what restore-time objective does a drill achieve?
- When should PostgreSQL 19 be adopted after general availability, given pgx currently documents testing against PostgreSQL 14-18?
