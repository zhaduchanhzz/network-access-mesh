# Research Evidence — G2

> Một phần của [nhật ký bằng chứng nghiên cứu](../research-evidence.md) (P0-T08). Chép nguyên từ kết quả của research agent ngày 2026-11-16; nhận định và trích dẫn giữ nguyên tiếng Anh.

## G2 - Headscale v0.29.7: policy engine (ACLs, grants, tests, SSH), tags, routes, exit nodes

**Tóm tắt của agent:** Headscale v0.29.7 has one policy engine (policy v2) that reads Tailscale-style HuJSON with exactly eleven top-level keys: groups, hosts, tagOwners, acls, grants, nodeAttrs, autoApprovers, ssh, tests, sshTests, randomizeClientPort. Unknown keys are rejected, so postures, ipsets, derpMap, disableIPv4 and OneCGNATRoute cannot be used. Grants are supported since 0.29.0 with src, dst, ip, app and via; srcPosture and all device-posture features are absent. ACLs are converted internally to grants and can be mixed with them; upstream recommends grants. The decisive default: no policy, or any policy that omits both acls and grants (including one that only defines tagOwners or ssh), is allow-all. An explicit empty array ("grants": [] or "acls": []) is deny-all. Tenant bootstrap must therefore push a policy containing "grants": [] before any user or key exists, and the generator must always emit that key. The API is sufficient for a central control plane: GET/PUT /api/v1/policy (PUT only with policy.mode: database) and POST /api/v1/policy/check, a dry-run that validates a candidate against live users and nodes and runs embedded tests and sshTests without persisting. Set-time validation rejects syntax errors, unknown fields, undefined groups/tags/hosts and ambiguous users; failing tests block the write. Missing and to be built in the platform: versioning, ETag or conditional writes, rollback, and any what-if preview of effective access. Tests are beta, depend on live inventory and evaluate only the global filter. Identity: users are referenced as email, name@ or providerId@. Groups are static, non-nestable lists, and OIDC groups cannot be used in rules, so the platform must write group membership into the policy and re-push on change. Role autogroups (admin, owner) do not exist. Tags are an exclusive identity; the admin API can set any policy-defined tag on any node and tag-only pre-auth keys exist, which fits platform-managed onboarding of servers and routers. Routes: double opt-in with API approval; autoApprovers are additive and re-evaluated on every policy push; subnet use is policy-gated; exit-node use is granted via autogroup:internet and steered per group with via. HA subnet routers work automatically with a sticky primary and control-channel health probes (10s/5s default); exit nodes have no control-plane failover. Propagation is push-based through a batcher ticking every tuning.batch_change_delay (800ms default) to connected nodes. No delivery or latency guarantee is documented, so revocation time must be measured. Main risks: grants, via, nodeAttrs, SSH check, tests and HA probing are all new in 0.29 (June 2026) and received fixes through 0.29.7. SSH accept rules always allow forwarding and there is no session recording. An invalid stored policy prevents startup, so every tenant policy must be validated before a Headscale upgrade. Caveat: Tailscale reference pages were read only through a summarising fetcher, so tailscale.com quotes are not byte-exact; all Headscale claims were read from raw source at the v0.29.7 tag.

## Nhận định

### G2-01 · `VERIFIED` · *critical* — Grants / support

- **Nhận định:** Headscale v0.29.7 supports the Tailscale grants syntax alongside ACLs in the same policy file. Grants were introduced in 0.29.0; upstream docs recommend grants and call ACLs legacy.
- **Bằng chứng:** docs/ref/policy.md: 'Headscale supports both ACLs and Grants to write an access control policy. We recommend the use of Grants since ACLs are considered legacy'. CHANGELOG 0.29.0 Grants: 'We now support Tailscale grants alongside ACLs.'
- **Nguồn:** https://raw.githubusercontent.com/juanfont/headscale/v0.29.7/docs/ref/policy.md ; https://raw.githubusercontent.com/juanfont/headscale/v0.29.7/CHANGELOG.md

### G2-02 · `VERIFIED` · *critical* — Grants / fields

- **Nhận định:** A grant object accepts exactly five fields: src, dst, ip, app, via. src and dst use the same alias list type as ACLs; dst carries no ports (ports and protocols go in ip).
- **Bằng chứng:** types.go: type Grant struct { Sources Aliases json:"src"; Destinations Aliases json:"dst"; InternetProtocols []ProtocolPort json:"ip,omitempty"; App tailcfg.PeerCapMap json:"app,omitzero"; Via []Tag json:"via,omitzero" }
- **Nguồn:** https://raw.githubusercontent.com/juanfont/headscale/v0.29.7/hscontrol/policy/v2/types.go

### G2-03 · `UNSUPPORTED` · *critical* — Grants / srcPosture and device posture

- **Nhận định:** srcPosture and the postures section are not supported: neither the Grant nor the Policy struct has such a field, the decoder rejects unknown members, and the docs list posture as a limitation.
- **Bằng chứng:** docs/ref/policy.md Limitations: 'Device postures and the related sections such as `postures` or `srcPosture` aren't supported.' types.go line 30: json.RejectUnknownMembers(true).
- **Nguồn:** https://raw.githubusercontent.com/juanfont/headscale/v0.29.7/docs/ref/policy.md ; https://raw.githubusercontent.com/juanfont/headscale/v0.29.7/hscontrol/policy/v2/types.go

### G2-04 · `VERIFIED` — Grants / validation and ip format

- **Nhận định:** A grant needs ip or app. ip entries are '*', '<ports>' or '<proto>:<ports>'. via entries must be tags defined in tagOwners. app cannot target autogroup:internet. dst 0.0.0.0/0 or ::/0 is rejected. '*' src with autogroup:self dst is rejected.
- **Bằng chứng:** types.go: ErrGrantMissingIPOrApp 'ip and app can not both be empty'; ErrGrantViaNotATag 'via can only be a tag'; ErrGrantAppWithAutogroupInternet; ErrGrantDefaultRouteCIDR; validateGrantSrcDstCombination; ProtocolPort.UnmarshalJSON.
- **Nguồn:** https://raw.githubusercontent.com/juanfont/headscale/v0.29.7/hscontrol/policy/v2/types.go

### G2-05 · `VERIFIED` — Grants / app capabilities

- **Nhận định:** app capabilities compile into CapGrant filter rules sent to destination nodes. Names must be domain/path without a URL scheme; tailscale.com/ names are limited to cap/drive, cap/relay, cap/webui, cap/kubernetes and cap/tsidp. Companion caps for drive and relay are generated automatically.
- **Bằng chứng:** types.go validateCapabilityName and tailscaleCapAllowlist {PeerCapabilityTaildrive, PeerCapabilityRelay, PeerCapabilityWebUI, PeerCapabilityKubernetes, PeerCapabilityTsIDP}; filter.go companionCaps; compiled.go compileOtherDests 'CapGrant rules from App'.
- **Nguồn:** https://raw.githubusercontent.com/juanfont/headscale/v0.29.7/hscontrol/policy/v2/types.go ; https://raw.githubusercontent.com/juanfont/headscale/v0.29.7/hscontrol/policy/v2/compiled.go

### G2-06 · `VERIFIED` · *critical* — Grants / via

- **Nhận định:** via is enforced for tagged subnet routers and exit nodes through per-node filter rules and per-viewer route steering. A via grant without ip compiles to nothing, and via grants never contribute to the global filter.
- **Bằng chứng:** compiled.go compileOneViaGrant: 'if len(grant.InternetProtocols) == 0 { return nil, nil }'; globalFilterRules: 'Via grants produce no global rules (they are per-node only)'; docs/about/features.md: '[x] Route filtering with Via'.
- **Nguồn:** https://raw.githubusercontent.com/juanfont/headscale/v0.29.7/hscontrol/policy/v2/compiled.go ; https://raw.githubusercontent.com/juanfont/headscale/v0.29.7/docs/about/features.md

### G2-07 · `VERIFIED` — ACLs / relation to grants

- **Nhận định:** ACL rules are converted internally into grants; ACL rules and grant ip entries compile to the same packet-filter rules (SrcIPs, DstPorts, IPProto). Both sections are additive and there is no deny action.
- **Bằng chứng:** compiled.go compileGrants: 'grants := pol.Grants; for _, acl := range pol.ACLs { grants = append(grants, aclToGrants(acl)...) }'; types.go Action.UnmarshalJSON accepts only 'accept' (ErrInvalidACLAction otherwise).

### G2-08 · `VERIFIED` · *critical* — Policy sections / accepted keys

- **Nhận định:** The policy accepts exactly eleven top-level keys: groups, hosts, tagOwners, acls, grants, nodeAttrs, autoApprovers, ssh, tests, sshTests, randomizeClientPort. Any other key fails with 'unknown field'; object members whose name starts with '#' are stripped as editor metadata.

### G2-09 · `UNSUPPORTED` — Policy sections / unsupported keys

- **Nhận định:** postures, ipsets, derpMap, disableIPv4 and OneCGNATRoute are not policy keys in Headscale. Docs state IP sets are unsupported and list randomizeClientPort as the only network-wide option; disable-ipv4 exists only as a per-node nodeAttr.
- **Bằng chứng:** docs/ref/policy.md: 'IP sets aren't supported.'; section 'Network-wide policy options' lists only `randomizeClientPort`; node attribute '`disable-ipv4`: Selectively disable IPv4'. Policy struct has no such fields.
- **Nguồn:** https://raw.githubusercontent.com/juanfont/headscale/v0.29.7/docs/ref/policy.md ; https://raw.githubusercontent.com/juanfont/headscale/v0.29.7/hscontrol/policy/v2/types.go

### G2-10 · `VERIFIED` — nodeAttrs

- **Nhận định:** nodeAttrs (new in 0.29.0) hands string capabilities to nodes matched by target: users, groups, tags, hosts, prefixes, autogroup:member, autogroup:tagged or '*'. ipPool and the funnel attribute are rejected at load.
- **Bằng chứng:** types.go NodeAttrGrant {target, attr, ipPool}; ErrNodeAttrIPPoolUnsupported; nodeAttrUnsupportedCaps{tailcfg.NodeAttrFunnel}. CHANGELOG 0.29.0: 'Policies that use the `funnel` cap, `ipPool` blocks, or `autogroup:admin` / `autogroup:owner` targets are rejected at load'.
- **Nguồn:** https://raw.githubusercontent.com/juanfont/headscale/v0.29.7/hscontrol/policy/v2/types.go ; https://raw.githubusercontent.com/juanfont/headscale/v0.29.7/CHANGELOG.md

### G2-11 · `VERIFIED` — ACL rule syntax

- **Nhận định:** An ACL rule has four fields: action (only 'accept'), proto, src, dst. Each dst is alias:ports with single ports, ranges, comma lists or '*'. proto accepts names (tcp, udp, icmp, ipv6-icmp, sctp, gre, esp, ah and others) or numbers; specific ports only with tcp, udp or sctp.
- **Bằng chứng:** types.go: type ACL struct { Action json:"action"; Protocol json:"proto"; Sources json:"src"; Destinations []AliasWithPorts json:"dst" }; Protocol.validate; validateProtocolPortCompatibility; utils.go parsePortRange.
- **Nguồn:** https://raw.githubusercontent.com/juanfont/headscale/v0.29.7/hscontrol/policy/v2/types.go ; https://raw.githubusercontent.com/juanfont/headscale/v0.29.7/hscontrol/policy/v2/utils.go

### G2-12 · `VERIFIED` — Alias kinds

- **Nhận định:** src/dst aliases are: '*', a user (token containing '@'), group:<name>, tag:<name>, autogroup:<name>, a hosts-section alias, or a literal IP or CIDR. No other selector type (ipset:, svc:) is parsed.
- **Bằng chứng:** types.go parseAlias: Prefix.parseString, then isWildcard, isUser, isGroup, isTag, isAutoGroup, isHost; otherwise ErrInvalidAlias 'invalid alias format'.
- **Nguồn:** https://raw.githubusercontent.com/juanfont/headscale/v0.29.7/hscontrol/policy/v2/types.go

### G2-13 · `VERIFIED` · *critical* — Autogroups

- **Nhận định:** Exactly six autogroups exist: autogroup:internet (dst only), autogroup:member, autogroup:tagged, autogroup:self (dst only), autogroup:nonroot (SSH users only), autogroup:danger-all (src only). Role autogroups such as admin and owner, and autogroup:shared, are rejected.
- **Bằng chứng:** types.go: var autogroups = []AutoGroup{AutoGroupInternet, AutoGroupMember, AutoGroupNonRoot, AutoGroupTagged, AutoGroupSelf, AutoGroupDangerAll}; autogroupForSrc, autogroupForDst; AutoGroup.Validate returns ErrInvalidAutogroup.
- **Nguồn:** https://raw.githubusercontent.com/juanfont/headscale/v0.29.7/hscontrol/policy/v2/types.go

### G2-14 · `VERIFIED` · *critical* — Wildcard semantics

- **Nhận định:** Since 0.29.0 '*' as a source means tailnet addresses (100.64.0.0/10, fd7a:115c:a1e0::/48) plus approved subnet routes. As a destination '*' is emitted to clients as IP '*' and is treated as reaching the internet, so it also covers subnet routes and exit-node use.
- **Bằng chứng:** CHANGELOG 0.29.0 BREAKING: 'Wildcard (`*`) ... now resolves to Tailscale's CGNAT range ... and ULA range'. filter.go destinationsToNetPortRange: 'use "*" directly instead of expanding'. policy.go grantReachesInternet returns true for Asterix. Effective scope worth a hands-on check.
- **Nguồn:** https://raw.githubusercontent.com/juanfont/headscale/v0.29.7/CHANGELOG.md ; https://raw.githubusercontent.com/juanfont/headscale/v0.29.7/hscontrol/policy/v2/filter.go ; https://raw.githubusercontent.com/juanfont/headscale/v0.29.7/hscontrol/policy/v2/policy.go

### G2-15 · `VERIFIED` — Alias resolution

- **Nhận định:** User and group aliases resolve only to untagged nodes of those users; tagged nodes are matched by tag only. hosts aliases and literal IPs resolve to exactly the literal prefix and do not expand to a node's other address family.
- **Bằng chứng:** types.go Username.resolve: 'Skip tagged nodes - they are identified by tags, not users'; Host.resolve: 'They do NOT expand to include the matching node's other IP addresses.'
- **Nguồn:** https://raw.githubusercontent.com/juanfont/headscale/v0.29.7/hscontrol/policy/v2/types.go

### G2-16 · `VERIFIED` · *critical* — Default behaviour / allow-all

- **Nhận định:** With no policy loaded, or with a policy that omits both acls and grants (for example '{}' or one defining only tagOwners, groups or ssh), Headscale installs an allow-all packet filter.
- **Bằng chứng:** docs/ref/policy.md: 'By default, no policy is loaded which means that Headscale allows all traffic between nodes.' policy.go updateLocked: 'if pm.pol == nil || (pm.pol.ACLs == nil && pm.pol.Grants == nil) { filter = tailcfg.FilterAllowAll }'.
- **Nguồn:** https://raw.githubusercontent.com/juanfont/headscale/v0.29.7/docs/ref/policy.md ; https://raw.githubusercontent.com/juanfont/headscale/v0.29.7/hscontrol/policy/v2/policy.go

### G2-17 · `VERIFIED` · *critical* — Default behaviour / deny-all

- **Nhận định:** An explicit empty array, "grants": [] or "acls": [], yields deny-all (empty filter). The difference between an omitted key and an empty array is intentional and unit-tested.
- **Bằng chứng:** policy_test.go: name 'empty-acls-denies-all', pol {"acls": []}, wantFilter nil; name 'empty-grants-denies-all'. docs/ref/policy.md: 'you can include an empty array for the "grants" section'. types_test.go TestUnmarshalPolicyEmptyArrays.

### G2-18 · `VERIFIED` — Default behaviour / SSH

- **Nhận định:** Tailscale SSH is deny-by-default regardless of the packet filter: with no ssh rules every node receives an explicit empty SSH rule list.
- **Bằng chứng:** filter.go compileSSHPolicy: 'if pol == nil || len(pol.SSHs) == 0 { return &tailcfg.SSHPolicy{Rules: []*tailcfg.SSHRule{}}, nil }' with comment 'SaaS sends "rules":[]'.

### G2-19 · `VERIFIED` · *critical* — Storage modes

- **Nhận định:** policy.mode is 'file' (default; path in policy.path; reloaded on SIGHUP) or 'database'. The API SetPolicy call is refused unless mode is database; GetPolicy and CheckPolicy work in both modes.

### G2-21 · `VERIFIED` · *critical* — Set-time validation

- **Nhận định:** Setting a policy rejects HuJSON syntax errors, unknown fields, and references to undefined groups, tags or hosts. Unknown users are tolerated (they resolve to an empty set); a user token matching several users is rejected.

### G2-22 · `VERIFIED` · *critical* — Tests at set time

- **Nhận định:** Embedded tests and sshTests run on every user-initiated write (API or CLI set, SIGHUP reload, check) in a sandbox built from the new policy and current users and nodes. Any failure rejects the write and leaves the live policy untouched. The feature is labelled beta.
- **Bằng chứng:** policy.go SetPolicy: 'if they fail, return without mutating the live PolicyManager so the failed write does not knock the running config offline'. test_test.go TestSetPolicyRejectsFailingTests. CHANGELOG 0.29.0: 'Policy tests (beta)'.

### G2-23 · `VERIFIED` · *critical* — Boot behaviour

- **Nhận định:** At startup failing tests only log a warning, but a stored policy that fails parsing or validation (including ambiguous user references) makes Headscale refuse to start.
- **Bằng chứng:** policy.go NewPolicyManager: 'policy tests failed at boot; server starting anyway, fix the policy and reload'. docs/about/faq.md: 'Headscale checks if the policy is valid during startup and refuses to start if it detects an error.'

### G2-24 · `VERIFIED` — policy check command

- **Nhận định:** 'headscale policy check --file <path>' is a thin client for the CheckPolicy RPC on a running server and validates against live users and nodes including tests. With --bypass-grpc-and-access-database-directly it opens the database itself and requires the server to be stopped.
- **Bằng chứng:** cli/policy.go Long: 'Check validates the policy against the server's live users and nodes, running any "tests" or "sshTests" block. By default the command is a thin frontend for a gRPC call to a running headscale'. A CHANGELOG 0.29.0 line describes older behaviour.
- **Nguồn:** https://raw.githubusercontent.com/juanfont/headscale/v0.29.7/cmd/headscale/cli/policy.go

### G2-25 · `VERIFIED` — Tests syntax

- **Nhận định:** tests entries have src (one alias), proto (tcp, udp, sctp or empty), accept and deny lists of host:port. Each destination must be one host and one port: no CIDR, port range or autogroup:internet. sshTests entries have src, dst, accept, deny, check. srcPostureAttrs is absent.
- **Bằng chứng:** test.go PolicyTest {src, proto, accept, deny} and SSHPolicyTest {src, dst, accept, deny, check}; types.go ErrTestDestinationMultiPort, ErrTestDestinationCIDR, ErrAutogroupInternetTestDst, ErrTestProtocolNotAllowed.

### G2-26 · `REQUIRES_VALIDATION` — Tests coverage

- **Nhận định:** ACL tests are evaluated against the global filter only, which excludes via grants and the autogroup:self part of rules. Whether access granted solely through via or autogroup:self can be asserted by tests is doubtful and needs a hands-on check.
- **Bằng chứng:** test.go evaluateTests: 'filter = globalFilterRules(grants)'; compiled.go: 'Via grants produce no global rules ... self grants contribute their non-self portion'. Test: policy with only autogroup:member to autogroup:self plus a tests entry asserting same-user access; observe accept or reject.

### G2-27 · `VERIFIED` · *critical* — Tests inventory dependence

- **Nhận định:** A test fails when its src user is not registered, when src resolves to no IP addresses, or when a destination resolves to no IP addresses. Tests therefore depend on the tenant's live users and nodes at apply time.
- **Bằng chứng:** test.go runPolicyTest: 'source %q resolved to no IP addresses'; errTestDestinationNoIP 'destination resolved to no IP addresses'; resolveTestSource: 'Rules tolerate unregistered users; a test naming one must still fail'.
- **Nguồn:** https://raw.githubusercontent.com/juanfont/headscale/v0.29.7/hscontrol/policy/v2/test.go

### G2-28 · `VERIFIED` — SetPolicy internals and storage

- **Nhận định:** The API handler applies the policy to the live manager first, then writes a new row to the policies table, then reloads and broadcasts. Rows are appended and reads return the newest row. GetPolicy returns an error ('acl policy not found') when no row exists.
- **Bằng chứng:** grpcv1.go SetPolicy: api.h.state.SetPolicy([]byte(p)) then api.h.state.SetPolicyInDB(p) then api.h.state.ReloadPolicy(). db/policy.go: Create(&p); 'SELECT * FROM policies ORDER BY id DESC LIMIT 1'; types.ErrPolicyNotFound.

### G2-29 · `UNSUPPORTED` · *critical* — Versioning and rollback

- **Nhận định:** The API offers no policy version identifier, ETag or conditional write, no history listing and no rollback call; requests carry only the policy string.
- **Bằng chứng:** policy.proto: 'message SetPolicyRequest { string policy = 1; }'; GetPolicyResponse has only policy and updated_at; headscale.proto policy block defines only GetPolicy, SetPolicy, CheckPolicy.
- **Nguồn:** https://raw.githubusercontent.com/juanfont/headscale/v0.29.7/proto/headscale/v1/policy.proto ; https://raw.githubusercontent.com/juanfont/headscale/v0.29.7/proto/headscale/v1/headscale.proto

### G2-30 · `VERIFIED` · *critical* — Dry-run validation API

- **Nhận định:** CheckPolicy (POST /api/v1/policy/check) is a dry-run: it validates a candidate policy against the server's live users and nodes and runs its tests without persisting or touching the live policy, in any policy.mode. Failures return InvalidArgument with the error text.
- **Bằng chứng:** grpcv1.go: 'CheckPolicy validates the given policy against the server's live users and nodes, running its `tests` block as a sandbox. Nothing is persisted and the live PolicyManager is not touched. Works regardless of policy.mode'.
- **Nguồn:** https://raw.githubusercontent.com/juanfont/headscale/v0.29.7/hscontrol/grpcv1.go

### G2-31 · `UNSUPPORTED` · *critical* — What-if evaluation

## Hệ quả thiết kế (agent đề xuất)

- Baseline tenant policy must contain an explicit empty rules array, for example {"groups":{}, "tagOwners":{...platform tags...}, "grants":[], "ssh":[], "autoApprovers":{"routes":{},"exitNode":[]}}. A policy without acls and grants keys is allow-all, so the generator must never omit "grants" and must never send an empty string.
- Bootstrap order per tenant: start the instance, create the API key, PUT the deny-all baseline, read it back, and only then create users or pre-auth keys. In database mode a fresh instance is allow-all until the first PUT; in file mode a deny-all file can be mounted before first boot.
- Use policy.mode: database for API-driven management (PUT /api/v1/policy is refused otherwise). The alternative is file mode with a mounted file plus SIGHUP, which removes the initial allow-all window but needs signal access to each container.
- Apply pipeline: render deterministic JSON from the platform model, lint against the eleven known keys, POST /api/v1/policy/check, PUT /api/v1/policy, GET to confirm content hash and updated_at, then record the result. Serialise writes per tenant because there is no ETag or conditional write.
- PostgreSQL is the source of truth for policy versions (rendered text, hash, author, reason, Headscale version). Rollback is a re-PUT of the last known good version; Headscale keeps old rows in SQLite but exposes only the newest.
- Keep generated tests separate from the versioned rules and regenerate them at apply time from current inventory: tests fail when a source or destination has no node, so a stored test block can block a rollback.
- Embedded tests are the only built-in impact check. For a real what-if view build either a platform-side evaluator or a shadow Headscale instance loaded with a copy of the tenant database, then diff /debug/filter or map responses before and after.
- Reference users by provider identifier with a trailing '@' (from GET /api/v1/user providerId) or by email; write portal or IdP groups into the policy groups section and re-push on membership change with debouncing. Model platform roles as generated groups because role autogroups do not exist.
- Declare every platform tag in tagOwners (owner lists can stay minimal so only the platform tags nodes) before issuing tagged pre-auth keys. Onboard servers, routers and exit nodes with single-use tag-only keys. Treat tagging as one-way.
- Prefer explicit route approval through the node API. Use autoApprovers only for platform-controlled router and exit tags, and to revoke a route remove both the approval and the autoApprovers entry, since every policy push re-approves matching routes.
- Never generate dst '*' in tenant rules: it also covers subnet routes and exit-node use. Grant internet egress only through autogroup:internet, optionally with via tags per group.
- Offer SSH as an opt-in feature with ssh: [] by default. If enabled, prefer check mode with portal approval through /api/v1/auth/approve, require Tailscale v1.104.4 or newer, document TS_SSH_DISABLE_FORWARDING, and state that session recording is unavailable.
- Device posture has to be a platform function: gate enrolment in the portal and remove or expire non-compliant nodes via the API; do not promise posture-conditional rules.
- Before any Headscale upgrade run every tenant's stored policy through CheckPolicy on a canary of the new version: an invalid stored policy stops the instance from starting, minor versions cannot be skipped and downgrades are blocked.
- Treat propagation as eventually consistent. Do not publish a revocation SLA until latency is measured; expose tuning.batch_change_delay as a platform-level setting only after testing.
- Deploy two routers per critical prefix and document failover of roughly 15 seconds or more; monitor HA health metrics. Do not rely on control-plane failover for exit nodes.

## Câu hỏi mở

- Revocation latency: time from PUT /api/v1/policy or node deletion to an established flow being blocked on peers, at 10, 100 and 500 nodes, including a peer that is offline and reconnects.
- Which HTTP status and body does PUT /api/v1/policy return for a validation or test failure? The handler wraps the error without a gRPC status code, so it may surface as a 500 rather than a 400.
- What happens if the database write fails after the handler has already applied the policy in memory (live policy differing from stored policy until restart)?
- Empty policy string: confirm that PUT with an empty string leaves the live policy unchanged but yields allow-all after restart, and make the platform reject it.
- Can tests assert access that exists only through autogroup:self or via grants, given that tests evaluate the global filter?
- Are empty owner lists in tagOwners and empty groups accepted by the parser (expected yes from code, not seen in a test)?
- Exact exit-node gating: can a user who may reach an exit node's tailnet IP but has no autogroup:internet grant select it as exit node? Confirm that dst '*' in practice permits exit-node and subnet use.
- Does the HA probe fail over a router that is connected but not forwarding (IP forwarding disabled, upstream link down)?
- via combined with HA: when the lowest-ID via-tagged router goes offline, do viewers fail over to another router with the same via tag?
- Effect on official clients of every node carrying the baseline Admin capability, given Headscale has no role model.
- A tagged pre-auth key whose tag is missing from tagOwners: the node gets a tag that rules cannot reference; decide whether the platform blocks this at key creation.
- Should policies use grants only, or keep acls for readability? Upstream recommends grants but they are five months old in Headscale.
- Do established connections drop immediately when a client receives a tightened filter, or only new flows? This is client behaviour and needs a test.
- Tailscale reference pages were read through a summarising fetcher; any wording relied on for a compatibility claim should be rechecked against the live page.
