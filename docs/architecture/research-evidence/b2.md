# Research Evidence — B2

> Một phần của [nhật ký bằng chứng nghiên cứu](../research-evidence.md) (P0-T08). Chép nguyên từ kết quả của research agent ngày 2026-11-16; nhận định và trích dẫn giữ nguyên tiếng Anh.

## B2 - fzhzyh/headscale-admin @0a4ca5e: feature routes, ACL engine and Headscale v0.29 API notes, cross-checked against juanfont/headscale v0.29.7 (proto, swagger, generated gateway, source, docs, CHANGELOG)

**Tóm tắt của agent:** The reviewed server is a carefully commented panel for exactly one Headscale instance. Its route layer is a thin and mostly accurate proxy over the Headscale v0.29 REST API, and most of its API notes hold. Against v0.29.7 proto, generated gateway, source and docs I confirmed: ExpireNode, RegisterNode and DeletePreAuthKey read only query parameters (the body is discarded); RenameNode changes givenName; approve_routes replaces the whole approved set without checking announcements; tags must exist in tagOwners; a policy without acls/grants is allow-all while an empty array is deny-all; policy writes need policy.mode=database (default is file); MoveNode no longer exists; pre-auth keys are stored as prefix plus bcrypt hash and shown once; Headscale has no traffic counters, no DNS API and no streaming API. Several statements in the notes are wrong for v0.29.7 and must not be copied into our design: /api/v1/policy/check is not syntax-only (it compiles against live users and nodes and runs the policy's tests/sshTests blocks); tagging is not strictly irreversible (client re-auth with --advertise-tags= --force-reauth reverts it); SSH has no deny action; groups accept usernames only; the ICMPv6 protocol name is ipv6-icmp; API keys are hskey-api-<12>-<64>. The ACL engine is the weakest reusable part. It evaluates only `acls`: grants (which upstream now recommends and into which it compiles ACLs), via, app and SSH are ignored. It treats a missing proto as TCP only, adds subnet routes to identity aliases, matches users by name, mishandles autogroup:self for tagged devices, and its unit-test fixtures encode behaviour upstream rejects. Topology status is derived entirely from this engine; nothing is measured. Recommendation: do not port the evaluator. Keep its UX ideas (trace output, allow-all/deny-all guard, version history including failed attempts, drift detection by updatedAt) and use Headscale itself as the oracle (policy tests through policy/check, /debug/filter). DNS management is limited to extra A/AAAA records written as one JSON file that Headscale hot-reloads through fsnotify; nameservers, split DNS, MagicDNS and base_domain remain config-file settings. This requires a shared filesystem between backend and each Headscale container: workable on one Docker host, a design problem for multi-host. Metrics are 15-second polls of the node list into InfluxDB 3 (online state, route counts, panel self-metrics) with no tenant dimension, no retention setting and explicitly no data-plane traffic (HTTP 501). Nothing is multi-tenant: one module-level Headscale client, global caches and poller, SQLite tables without tenant columns, per-instance numeric IDs used as keys. Reuse is therefore at the level of patterns and verified API knowledge, not code (it is TypeScript, not Go). Three behaviours still need a hands-on test: HTTP status codes for plain upstream errors, pre-auth keys created without expiration, and tagOwners removal.

## Hệ quả thiết kế (agent đề xuất)

- Provision every tenant Headscale with `policy.mode: database`; the default is `file` and API policy writes fail otherwise. Normalise the 'acl policy not found' error to 'no policy = allow-all'.
- Make the policy model grants-first (upstream calls ACLs legacy and compiles them to grants); treat `acls` as import-only. Never normalise a missing acls/grants key to an empty array: that flips allow-all to deny-all.
- Do not port the third-party evaluator. Use Headscale as the oracle: send candidate policy plus generated `tests` entries to POST /api/v1/policy/check (beta; one src, single-port TCP/UDP/SCTP destinations, no CIDR or autogroup:internet) and, where reachable on the private network, read the compiled filter from /debug/filter.
- The Go Headscale client must send query parameters (not JSON) for node expire, node register, pre-auth key delete and backfill; treat year-1 expiry as 'never'; derive ownership from `tags` rather than the `user` field; expect masked key prefixes in listings.
- Offer no 'move device to another user' feature (removed upstream). Word the tagging warning accurately: the admin API cannot remove all tags, but a client can return to user ownership by re-authenticating with `--advertise-tags= --force-reauth`.
- DNS needs two mechanisms per tenant: (a) an extra-records JSON file in a dedicated directory mount, created as valid `[]` at provisioning and replaced by temp-file-plus-rename; (b) config.yaml templating plus a controlled restart for nameservers, split DNS, search domains, MagicDNS and base_domain. Multi-host needs an agent or shared storage for (a).
- Model exit-node approval as one boolean per node (upstream pairs 0.0.0.0/0 and ::/0) and send complete approved-route sets with optimistic concurrency, since approve_routes replaces the whole set and does not check announcements.
- Keep policy version history in central PostgreSQL keyed by tenant: store every attempt including failures, the Headscale updatedAt for drift detection, and run validation plus policy/check before rollback. Headscale keeps policy rows but exposes no history API.
- Generate policy `groups` from central membership data: usernames only, no nesting, no tags. Resolve users by Headscale user ID or OIDC provider identifier, not by display name.
- Pre-auth keys: never persist or log plaintext, show once, support tag-only keys (user omitted) for service nodes, always send an explicit expiration, and never place keys in URLs.
- Metrics: poll each tenant (no streaming API), tag every series with tenant ID and use (tenant, node) composite keys because node IDs are per-instance sequences; define retention explicitly; plan data-plane traffic accounting as a separate design (Headscale has none).
- Pre-validate inputs centrally (lowercase `tag:` format, tag present in tagOwners, user has no nodes, duplicate user name) because Headscale answers several of these with plain errors rather than typed status codes.
- Fleet policy: minimum Tailscale client v1.80.0 for Headscale 0.29.x; Headscale blocks skipping minor versions and downgrades, so per-tenant instances must be upgraded one minor at a time; API keys default to 90-day expiry and need a rotation job.
- Resource catalog: keep addresses in policy `hosts` and ports in rules, but run sync through the same permission, validation and failure handling as any policy push, and preserve HuJSON comments.

- Is using /api/v1/policy/check as an access oracle fast enough for interactive checks, and what replaces it for an N-squared topology view (the compiled filter from /debug/filter on the metrics listener, or a Go engine)?
- For nodes registered with a tagged pre-auth key created by a user, does GET /api/v1/node/{id} return the creating user (the 'created by' UserID) or null? This affects ownership display.
- Confirm on a live instance that approving only ::/0 (or only 0.0.0.0/0) re-approves both exit routes, i.e. that a single-family disable is a no-op.
- How should GET /api/v1/node?user=<name> and `user@` policy tokens be handled when OIDC users share or lack names (upstream errors on multiple matches)?
- Is the policy `tests` feature stable enough to depend on while marked beta, and is its error text format stable enough to parse?
